# photo-bot — Telegram-бот для улучшения фотографий

Бот принимает фото (лучше — файлом), сам анализирует его и сразу возвращает
улучшенный снимок: файлом без сжатия, превью и сравнением «до / после».
Под результатом — кнопки «Слабее» / «Сильнее» (5 уровней силы).
Используются классические алгоритмы OpenCV и, по выбору, компактная нейросеть
Real-ESRGAN (realesr-general-x4v3, ONNX, onnxruntime на CPU).
Работает как Python serverless-функция на Vercel в режиме webhook.

## Умный режим (по умолчанию)

Выбирать ничего не нужно: пользователь присылает фото, бот анализирует кадр и включает только
нужные шаги (`Mode.SMART`, `bot/pipeline.py::_smart_steps`). Порядок:

1. выравнивание и слияние — только для серий;
2. **устранение смаза** — если оценка смаза по кадру σ ≥ 0,8 px (деконволюция до нейросети:
   она усиливает шум, а нейросеть его потом убирает);
3. **резкость лиц** — если найдены лица и лицо смазано сильнее кадра: смаз оценивается по рамке
   лица, область восстанавливается своим ядром и вклеивается по маске кожи;
4. **Real-ESRGAN** — модель по шуму (x4v3 / смесь 50/50 / wdn), маленькие кадры ×4, большие —
   в исходном размере; на лицах переносится больше реальных деталей оригинала (против «пластика»);
5. запасные деблокинг и шумоподавление — только если нейросеть не применилась;
6. **удаление дымки** — если в кадре нет настоящего чёрного и тёмный канал высок;
7. **тени и света** — если много тёмного (контровой свет) или выбитых областей;
8. цветокоррекция и адаптивный CLAHE;
9. **выравнивание горизонта** — если длинные линии согласованно завалены на 0,5–6°
   (поворот с обрезкой до тех же пропорций; после шагов по лицам, т. к. сдвигает координаты);
10. мягкая резкость без ореолов — последней.

**Сила** — 5 уровней (`STRENGTH_LEVELS`: 0,5 / 0,75 / 1 / 1,3 / 1,6). Она масштабирует деконволюцию,
дымку, тени и света, цвет, CLAHE, резкость и сдвигает выбор модели: «Слабее» — к wdn (меньше
сглаживания), «Сильнее» — к x4v3. Кнопки под файлом-результатом переделывают фото из оригинала:
результат — ответ на сообщение с фото, поэтому исходник берётся из `reply_to_message`, хранилище не нужно.
Кнопки со старого результата снимаются, чтобы двойной тап не запускал две обработки.

Ограничения: каскады Хаара находят в основном лица анфас; лица в профиль или сильно опущенные
могут не найтись (тогда обработка как без лиц). Сильно размытое лицо классическая деконволюция
не восстановит — для этого нужны нейросети для лиц (GFPGAN, CodeFormer), они не помещаются
в лимит функции Vercel и не входят в ТЗ.

## Остальные режимы

Раньше режим выбирался кнопками. Эти кнопки убраны, но режимы остались в коде (`Mode`), и кнопки
на уже отправленных сообщениях продолжают работать.

| Кнопка | Шаги |
|---|---|
| Авто | деблокинг JPEG (если найдена сетка блоков) → шумоподавление по зонам яркости (если σ > 2) → цветокоррекция → адаптивный CLAHE → лёгкая резкость без ореолов |
| Шум | деблокинг (если нужен) → шумоподавление по зонам яркости |
| Резкость | деблокинг (если нужен) → нерезкое маскирование без ореолов |
| Размытие | деблокинг (если нужен) → деконволюция Ричардсона–Люси с ядром, оценённым по кадру (сила и направление смаза), без «звона» |
| Полный конвейер | деблокинг → шумоподавление по зонам → умная деконволюция → цветокоррекция → адаптивный CLAHE → мягкая резкость |
| Авто + нейросеть | Real-ESRGAN, модель по шуму (σ > 3,5 → x4v3, 1,5–3,5 → смесь x4v3/wdn 50/50, иначе wdn) → цветокоррекция → адаптивный CLAHE → умеренная резкость; если нейросеть не применилась — деблокинг и шумоподавление как в «Авто» |
| Нейросеть ×4 | Real-ESRGAN realesr-general-x4v3 → CLAHE → умеренная резкость |
| Нейросеть ×4, детали | то же с realesr-general-wdn-x4v3 |

### Цвет, шум и метаданные

- **Цветокоррекция** (`bot/algorithms/color.py`, в «Авто», «Полном» и «Авто + нейросеть»):
  баланс белого по «серому миру» только по средним тонам, исправляется 60 % сдвига, коэффициенты
  каналов ограничены 0,8–1,25, сдвиг меньше 3 % не трогается — тёплые и «киношные» кадры не
  выстуживаются в серость. Автоуровни растягивают яркость между перцентилями 0,4/99,6 %, не более
  чем в 1,6 раза и только если гистограмма сжата. Вибрация усиливает бледные цвета, почти не трогает
  насыщенные и защищает тона кожи.
- **Шум яркости и цвета раздельно:** NLM чистит цвет (a/b) в 1,8 раза сильнее, чем яркость.
  Цветные пятна в тенях уходят, а яркостная текстура не превращается в «пластик».
- **ICC-профиль и EXIF сохраняются** (Pillow): файл-документ получает профиль исходника
  (важно для Display P3 с iPhone и Android — иначе цвета тускнеют) и EXIF с ориентацией,
  сброшенной в 1 (пиксели уже повёрнуты). Превью и «до / после» переводятся в sRGB, потому что
  Telegram выбрасывает профиль из фото. JPEG сохраняется без субсэмплинга цвета (4:4:4).

### Шумоподавление, контраст, резкость, деблокинг, деконволюция

- **Шум по зонам яркости** (`denoise_by_luma`): шум оценивается отдельно в 5 зонах яркости (робастно,
  по медиане отклика Immerkær). NLM запускается один раз с силой под самую шумную зону (обычно тени),
  а результат подмешивается с весом σ_зоны/σ_max: тени чистятся полностью, чистые света — частично,
  и мелкая текстура там сохраняется. Время — как у обычного NLM.
- **Адаптивный CLAHE:** сила зависит от контраста кадра (плоский — сильнее, контрастный — слабее,
  0,6–1,4 от базовой), а на ровных участках (небо, стены — локальный разброс на уровне шума)
  эффект ослабляется до 15 %, чтобы не вытягивать зерно и ступеньки.
- **Резкость без ореолов:** результат нерезкого маскирования ограничивается локальными min/max
  исходника (окно 3×3, допуск 10 % размаха). Склон края тот же, светлые и тёмные каймы срезаются.
- **Деблокинг JPEG:** детектор ищет 8×8 сетку и её сдвиг по превышению перепадов на границах блоков
  (≥ 1,3 раза). Масштабированные после сжатия кадры и несжатые не трогаются. Ступеньки на границах
  блоков в ровных местах превращаются в плавный переход на 6 px; ступеньки больше порога (настоящие
  края) не меняются. Порог берётся из типичной ступеньки на границах этого кадра.
- **Умная деконволюция:** σ смаза оценивается методом повторного размытия по сильным краям отдельно
  для 12 направлений (σ = σ0/√(R²−1), с поправкой на погрешность дискретных производных). Получаются
  сила, вытянутость и направление смаза → вытянутое гауссово ядро. Резкий кадр (σ < 0,6) не меняется,
  σ ограничена 3 px. Деконволюция идёт по каналам RGB (по одной яркости в Lab она не восстанавливает
  цветные края), «звон» срезается ограничением по локальному диапазону исходника в окне ≈ 3σ.
  В подписи шага видно, что найдено: «размытие σ≈1,4 px» или «смаз σ≈2,1 px, направление 90°».

### Нейросетевой шаг

- Порядок фиксирован: ECC (серии) → слияние (серии) → Real-ESRGAN → CLAHE → нерезкое маскирование.
  Нерезкое маскирование всегда последнее в любом режиме (`order_steps`), остальные флаги независимы.
  Шаг может быть запасным (`Step.fallback_for`): он выполняется, только если основной шаг не применился.
  Так в «Авто + нейросеть» классическое шумоподавление срабатывает лишь при пропуске нейросети.
- Вход уменьшается до `SR_MAX_SIDE` (1024 px) по длинной стороне. Размер результата — `SR_OUTPUT`:
  `auto` (по умолчанию) — маленькие кадры (≤ 1024 px) увеличиваются ×4, большие возвращаются
  **в исходном размере с переносом деталей**: основа и цвет — от нейросети, а мелкие детали оригинала,
  которые заметно сильнее шума (порог ~2,5σ), переносятся обратно. Так большое фото не «дорисовывается».
  `x4` — всегда ×4, `original` — всегда исходный размер. Инференс идёт тайлами `SR_TILE` (384 px) с перекрытием 16 px:
  пик памяти ~390 МБ вместо ~820 МБ, время +12 %, швов не видно (расхождение со сплошным
  инференсом — до 6 уровней на отдельных пикселях, в среднем 0,002).
- **x4v3 или wdn.** В официальном `inference_realesrgan.py` параметр `-dn 1` («сильное шумоподавление») —
  это чистая x4v3, а `-dn 0` («слабое, шум сохраняется») — чистая wdn. Поэтому для шумных кадров нужна
  обычная кнопка «Нейросеть ×4», а «детали» (wdn) меньше сглаживает и сохраняет текстуру.
- После каждого тайла оценивается полное время. Если прогноз больше `SR_TIMEOUT` (200 с), шаг
  прерывается сразу, пользователь получает классический результат (CLAHE + резкость в исходном
  размере) с пояснением. Так же шаг пропускается, если нет файла модели или onnxruntime.
- Модели лежат в `models/` (по 4,64 МБ): x4v3, wdn-x4v3 и их смесь 50/50 (`dn05`, DNI-интерполяция весов,
  как `-dn 0.5` в официальном скрипте; используется в «Авто + нейросеть» при среднем шуме). Официально веса публикуются только как `.pth`
  ([релиз v0.2.5.0](https://github.com/xinntao/Real-ESRGAN/releases/tag/v0.2.5.0)); ONNX получены
  скриптом `scripts/export_onnx.py`: он проверяет sha256 весов и сверяет выход ONNX с PyTorch (расхождение ≤ 1e-5).

Деконволюция запускается только в режимах «Размытие» и «Полный конвейер», т. е. по явному выбору.
Для серий кадров (вторая итерация) в начало любого режима добавляются выравнивание ECC
(евклидова модель) и слияние: Mertens, если экспозиции различаются, иначе усреднение.
Алгоритмы уже реализованы и покрыты тестами (`bot/algorithms/align.py`, `hdr.py`), не хватает только сборки альбома в хранилище.

Каждый шаг конвейера — запись `Step(name, title, kind, func, enabled)` в списке
(`bot/pipeline.py`); шаг можно выключить через `enabled` или `toggle()`.
Если шаг упал, он пропускается, остальные выполняются, а пользователь видит в отчёте, что именно не вышло.

## Почему aiogram 3

ТЗ предлагает aiogram 3.x, причин менять его нет: он асинхронный (хорошо ложится на ASGI-функцию),
позволяет скормить диспетчеру одно обновление (`dp.feed_update`) без поллинга и встроенного веб-сервера
и не держит состояние между запросами. Bot создаётся на каждый запрос и закрывается после него, потому что
сессия aiohttp привязана к event loop, а в serverless loop может смениться.

## Как это устроено без хранилища

Кнопки режимов бот присылает ответом (reply) на сообщение с фото. При нажатии кнопки Telegram присылает
это сообщение вместе с `reply_to_message`, откуда берётся `file_id` исходника. Поэтому первой итерации
внешнее хранилище не нужно. Оно (Upstash Redis / Vercel KV) подключается по желанию и даёт:

- `/mode` — режим по умолчанию: фото обрабатывается сразу, без кнопок;
- защиту от двойной обработки, если Telegram повторит доставку обновления (`SET NX` по `update_id`).


## Локальный запуск

Polling не используется, поэтому локально бот тоже работает через webhook — нужен https-туннель.

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows; на Linux/macOS: source .venv/bin/activate
pip install -r requirements-dev.txt
copy .env.example .env          # именно копия: шаблон остаётся; заполнить TELEGRAM_BOT_TOKEN и WEBHOOK_SECRET
pytest
```

Запуск сервера (переменные из `.env` подхватываются через `--env-file`):

```bash
uvicorn api.webhook:app --port 8000 --env-file .env
```

В другом терминале — туннель, например `cloudflared tunnel --url http://localhost:8000` или `ngrok http 8000`,
затем регистрация webhook на адрес туннеля:

```bash
python scripts/set_webhook.py --url https://<адрес-туннеля>
```

Важно: у бота может быть только один webhook. Перед возвратом на Vercel снова выполните `set_webhook.py` без `--url`.

## Деплой на Vercel

1. Установите Vercel CLI (`npm i -g vercel`) и выполните `vercel login`.
2. В корне проекта: `vercel link`, затем задайте переменные:
   ```bash
   vercel env add TELEGRAM_BOT_TOKEN production
   vercel env add WEBHOOK_SECRET production
   ```
   (по желанию — `PROCESS_TIMEOUT`, `ALLOWED_USER_IDS`, `KV_REST_API_*`; хранилище удобно подключить
   из Marketplace → Upstash Redis, переменные `KV_REST_API_URL/TOKEN` пропишутся сами).
3. `vercel --prod`. Проверка: `GET https://<проект>.vercel.app/api/webhook` отвечает `photo-bot webhook is alive`.
4. Пропишите `PUBLIC_URL` в `.env` локально и зарегистрируйте webhook:
   ```bash
   python scripts/set_webhook.py
   python scripts/set_webhook.py --info
   ```

### Лимиты функции

- `vercel.json`: `maxDuration: 300`, `memory: 2048`, `includeFiles: models/*.onnx`. 300 с доступны на Hobby
  при включённом Fluid compute (по умолчанию для новых проектов). Без Fluid compute Hobby ограничен 60 с —
  тогда нейросетевые режимы не успеют: отключите их (`SR_ENABLED=0`), поставьте `maxDuration: 60`
  и `PROCESS_TIMEOUT=40`.
- `PROCESS_TIMEOUT` (270 с) ограничивает всю обработку, `SR_TIMEOUT` (200 с) — только нейросеть, чтобы после
  её пропуска хватило времени на классический результат и отправку файлов.
- Замер в один поток (как 1 vCPU на Vercel), Ryzen 7 8845H, пережатый размытый кадр 12 Мп:
  «Авто» ≈ 8 с (+ ≈ 27 с, если нужно шумоподавление), «Резкость» ≈ 3 с, «Шум» ≈ 29 с,
  «Размытие» ≈ 34 с (деконволюция по RGB при сильном смазе — до ≈ 32 с), «Полный» ≈ 39–67 с,
  нейросетевые режимы ≈ 38–42 с. Пик памяти процесса ≈ 1,3–1,6 ГБ при лимите функции 2 ГБ.
  На Vercel CPU, скорее всего, медленнее; запас до 200/270 с большой.
- `MAX_MEGAPIXELS=16` по умолчанию: крупные кадры уменьшаются, чтобы NLM гарантированно уложился в таймаут.
- Размер функции: `opencv-python-headless` + `numpy` + `aiogram` + `onnxruntime` + модели ≈ 300 МБ
  в распакованном виде, при лимите Vercel для Python 500 МБ. Если сборка упрётся в лимит — это будет
  видно в логе деплоя; тогда это обсуждается до продолжения работ, как требует ТЗ.
- Долгая обработка: если функция отвечает дольше, чем ждёт Telegram, он может повторить доставку.
  Повтор отбрасывается по `update_id` — в памяти инстанса и, если подключено, в KV (надёжнее).
- Telegram: бот скачивает файлы до 20 МБ и отправляет до 50 МБ. PNG/TIFF возвращаются в PNG; если PNG
  выходит больше 49 МБ, результат пересохраняется в JPEG 95.

## Минусы нейросетевой части

Нейросеть здесь простая, и это осознанный компромисс под лимиты Vercel, а не лучший выбор по качеству:

- **Модель компактная** (SRVGG, около 4,6 МБ весов), а не полноразмерный Real-ESRGAN. На сложных текстурах
  и мелких деталях она даёт мыльность или перерисовывает их.
- **Дорисовывает то, чего не было.** Нейросеть генерирует правдоподобную деталь, а не восстанавливает реальную.
  Текстура ткани, волосы, буквы и мелкий текст могут выглядеть уверенно, но быть неверными. Для документов,
  номеров и подписей нейросетевые режимы не подходят.
- **Лица выглядят «пластиково».** Специализированных моделей для лиц (GFPGAN, CodeFormer) здесь нет, поэтому
  при обработке лиц переносятся только часть реальных деталей оригинала.
- **Одна модель на все кадры.** Нет подбора под конкретный снимок: выбор между `x4v3` и `wdn` делается
  эвристикой по оценке шума, и она может ошибиться.
- **Вход сжимается до 1024 px.** Нейросеть видит меньше деталей большого кадра. Режим `auto` возвращает
  большие фото в исходном размере с переносом деталей, но это лишь частично компенсирует потерю.
- **Скорость и результат зависят от нагрузки.** Замер ≈ 38–42 с на одном потоке для кадра 12 Мп, на Vercel
  может быть медленнее. Если прогноз превышает `SR_TIMEOUT`, шаг пропускается, и пользователь получает
  классический результат. Один и тот же снимок может дать разный итог в зависимости от того, успел ли шаг.
- **Лишний вес и холодный старт.** onnxruntime и веса увеличивают размер функции и время первого запуска.
- **Модель не обновляется сама.** Веса официально публикуются в `.pth`, ONNX получен через `scripts/export_onnx.py`.
  Чтобы сменить модель, нужно заново экспортировать и проверить её.
- **Нет проверки качества.** Бот не оценивает, стало ли фото лучше. Результат нейросети нужно смотреть глазами,
  особенно на сильно смазанных и шумных кадрах.

## Известные ограничения первой версии

- Альбомы (media group) пока обрабатываются покадрово: на каждый кадр приходят свои кнопки.
- Без KV повтор доставки обновления, попавший на другой инстанс функции, может привести к повторной
  обработке; с KV повтор отбрасывается всегда.
- HEIC не читается OpenCV — бот просит прислать JPEG.

## Тесты

```bash
pytest -q
```

- `test_algorithms.py` — каждый алгоритм сохраняет форму и dtype; NLM снижает шум; CLAHE поднимает
  локальный контраст; резкость усиливает границы; RL восстанавливает размытую картинку; ECC компенсирует сдвиг;
  усреднение снижает шум; Mertens работает на серии экспозиций.
- `test_quality.py` — цветокоррекция (сдвиг уменьшается, тёплый кадр не выстуживается, кожа защищена),
  цвет чистится сильнее яркости, ICC/EXIF доходят до результата, JPEG 4:4:4, перенос деталей
  возвращает реальные детали и не возвращает шум.
- `test_quality2.py` — резкость без ореолов, адаптивный CLAHE бережёт ровные участки, детектор JPEG-сетки
  (и её сдвига) и деблокинг без порчи краёв, оценка силы и направления смаза, умная деконволюция,
  шум по зонам яркости, деблокинг включается только при найденной сетке.
- `test_quality3.py` — дымка (находится и убирается, без ложных срабатываний на белых объектах),
  тени и света при контровом свете, маска и деконволюция лиц, перенос деталей на лицах, горизонт
  (угол, остаток после поворота, без срабатываний на ровных/сильно наклонённых/диагональных),
  умный режим (включает только нужные шаги, порядок, уровни силы).
- `test_superres.py` — обе модели на месте и дают ×4, тайлы совпадают со сплошным инференсом, x4v3 давит шум
  сильнее wdn, превышение бюджета и отсутствие модели дают понятные исключения.
- `test_pipeline.py` — режимы, фиксированный порядок нейросетевого конвейера, резкость всегда последняя,
  независимые флаги, откат на классику при нехватке времени, пропуск упавшего шага, остановка по таймауту.
- `test_handlers.py` — webhook отклоняет запросы без секрета (403), отвечает 200 при внутренней ошибке,
  `/start` и `/help` отправляют ответ, фото сразу обрабатывается и возвращается документом с кнопками
  «Слабее»/«Сильнее», кнопки переделывают с другим уровнем, нечитаемый файл даёт понятное сообщение
  (запросы к Telegram подменены фейковой сессией).
